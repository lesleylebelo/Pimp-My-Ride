## Compatibility verification

Official documentation checked on 2026-10-23:

- [Model specification](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite): exact stable model ID gemini-3.5-flash-lite, text output and structured outputs.
- [generateContent structured output guide](https://ai.google.dev/gemini-api/docs/generate-content/structured-output): lists this model, responseJsonSchema/responseMimeType, objects, required properties, nullable types, enum, additionalProperties and arrays.
- [Migration guidance](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.6): Gemini 3 no longer accepts candidateCount. Existing requests already omit deprecated sampling parameters and end with a user turn.
- [Thought signatures](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures): Gemini 3 text parts can include thoughtSignature metadata.
- [Pricing](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite): public Standard-tier input/output are listed as free on the Free tier. Public pricing alone does not establish individual project/key access.

The adapter explicitly allows only gemini-2.5-flash-lite and
gemini-3.5-flash-lite. There is no default model, dynamic model discovery,
automatic retry, alias expansion or fallback to another model/provider. OpenAI
remains inactive: explicit OpenAI selection and omitted provider still fail closed,
even with an OpenAI key present. This patch does not remove or reintroduce an
OpenAI implementation; the production baseline's adapter is already Gemini-only.

For 3.5 the adapter calls exactly:
https://generativelanguage.googleapis.com/v1beta/models/gemini-3.5-flash-lite:generateContent
using the existing server-only key header. The request omits candidateCount;
legacy 2.5 retains its original request shape. Response parsing still demands
exactly one completed, unblocked model candidate. For 3.5 only, a string
thoughtSignature may accompany text; it is discarded, never logged, returned,
persisted, added to later requests or included in diagnostics. Non-text parts,
thinking summaries, incorrectly typed signatures and unknown fields remain
rejected. No conversation history, tools or new provider SDK is introduced.

The unchanged JSON contract requires title and description strings, categoryId
as a supplied category ID or null, and at most five missingDetails strings.
The request schema is identical for both models, including additionalProperties:
false. Backend length, category, question-format, number, negation and factual-
grounding validation remains identical to main. String-length constraints cannot
be relied on as provider enforcement; existing backend checks are authoritative.
The original 1,800-output-token bound and 15-second timeout remain. Real latency,
truncation rates and output quality remain untested; no limits were increased.

The five-attempt global UTC-day control, crash/uncertain handling, diagnostics,
test UID allowlist, Firebase auth, active/approved-account checks and historical
record handling are byte-identical to main. Model changes cannot reset quota.
