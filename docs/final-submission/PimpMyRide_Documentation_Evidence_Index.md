## 1. Evidence categories

**High/source** means a claim is directly supported by inspected code/configuration. **High/recorded** means an existing execution summary/log was inspected. **Reported** means the repository records information supplied by its owner. **Unverified live** means source/tests do not establish current cloud operation. Confidence concerns the stated narrow claim, not unconditional application correctness.

## 4. Contradiction-resolution rules used

1. Current source/registered routes take precedence over an older handover's broad feature list.
2. Current provider source and the saved-agent compatibility report supersede earlier notes that still mention a request-level reasoning override.
3. The mock gate/provider/simulation markers take precedence over the historical root README statement that payment acceptance is only a local gate. Current code permits explicit simulation on the existing configured backend; live enabled state was not read.
4. Current new-media scope is private; legacy `public-posts` compatibility does not imply public new showcase buckets.
5. Registered Customer routes and disabled non-shop publishing controls take precedence over legacy backend customer-build handlers when describing available screens.
6. Saved execution counts retain their original scope. Earlier native exports and emulator results do not become final-Studio device acceptance merely because they passed.
7. Generated Netlify configuration proves a recorded configuration path, not portable/current hosted settings. Render target files do not prove the deployed branch.
